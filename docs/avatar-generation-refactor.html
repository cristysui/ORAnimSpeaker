角色动画生成能力改造说明

本文总结当前项目在原有视频编辑器基础上，围绕“序列帧图片生成视频”和“动作视频生成视频/动作覆盖”两类角色动画能力做的改造。 重点覆盖数据结构、素材配置、音频驱动生成、手动动作覆盖、预览合成和近期修正点。

项目：ORAnimSpeaker 应用：apps/web 整理日期：2026-06-05 核心模块：features/avatar

一、改造目标

序列帧图片生成视频

支持将多张角色图片按固定或单帧时长组成动作序列，并在生成时编码为 WebM 视频片段，作为时间线中的角色动画素材使用。

动作视频生成角色动画

支持直接配置静止、说话、手动动作视频素材，根据音频分析结果自动铺设 idle/speaking 片段，也可在播放头位置插入动作覆盖片段。

统一时间线承载

生成结果不另建独立播放器，而是落到原项目 timeline 的轨道、clip、mediaLibrary 中，复用现有预览、导出和编辑能力。

三、数据模型改造

角色能力挂在项目级 metadata 上：project.metadata.avatar。 配置分成 videoConfig 和 sequenceConfig，二者都包含 idle、speaking、actions 三类动作。

类型 用途 关键字段
AvatarVideoAsset 单个视频动作素材。 id、mediaId、name、kind、transform
AvatarSequenceAction 一个由多张图片组成的序列帧动作。 id、name、kind、frameDurationSec、frames、transform
AvatarSequenceFrame 序列帧动作中的单张图片。 id、mediaId、name、durationSec
AvatarGeneratedClipMetadata 标记自动生成出来的角色动画 clip。 kind: "avatar-generated"、source、audioClipId、characterId
AvatarActionOverlayMetadata 标记手动动作覆盖 clip，并绑定父角色 clip。 kind: "avatar-action-overlay"、source、parentGeneratedClipId、actionId
近期修正点：generateAvatarFromSequence 生成的角色片段 metadata 已从 source: "video" 修正为 source: "sequence"。这让预览层能识别序列帧生成片段，并避开不适合该类合成的原生视频播放路径。

四、素材配置能力

1. 动作视频配置

  • 入口位于 AvatarPanel.tsx 的“视频配置” tab。
  • 静止和说话为必填动作；手动动作可继续添加、重命名、删除。
  • 导入视频时会通过浏览器读取视频 metadata，并生成首帧缩略图。
  • 每个视频动作保存为 AvatarVideoAsset，实际文件进入项目 mediaLibrary。

2. 序列帧图片配置

  • 入口位于 AvatarPanel.tsx 的“序列帧配置” tab。
  • 支持设置全局单图时长，当前限制为 0.1 秒到 2 秒。
  • 每个动作可一次导入多张图片，形成 AvatarSequenceAction.frames。
  • 支持继续添加帧、删除单帧、拖拽排序、重命名手动动作。
  • 静止和说话动作至少各有一个非空序列，才允许从序列帧生成角色动画。

五、音频驱动生成流程

AvatarGenerationStrip.tsx 会扫描时间线中的音频 clip。只要对应类型配置完整，就显示生成按钮。 生成入口分别调用 generateAvatarFromVideo(audioClipId) 和 generateAvatarFromSequence(audioClipId)。

1. 找到音频 根据用户选择的 audioClipId 在项目 timeline 中定位音频 clip 和所在轨道。
2. 分析音频 调用 analyzeAudioBlob，得到 speaking/idle 分段，并裁剪到音频时长范围内。
3. 规范分段 合并连续同状态片段，过滤过短变化，并把开头 2 秒内进入说话的 idle 合并为 speaking。
4. 生成 clip 按分段状态从 idle 或 speaking 素材池循环取素材，生成角色动画 clip。
5. 插入轨道 新建“人物视频动画”或“人物序列帧动画”轨道，插入到音频轨道之前。

动作视频路径

视频路径直接使用配置好的 AvatarVideoAsset.mediaId。 每个 speaking/idle 分段会按素材原始时长切片，不足时循环取同类素材，直到覆盖对应音频分段。

序列帧路径

序列帧路径会先把 idle 和 speaking 的 AvatarSequenceAction 预渲染成临时 WebM 视频素材。 当前每个序列动作会展开为约 5 秒的循环帧计划，再通过 Mediabunny 的 CanvasSource 编码为带 alpha 保留的 WebM。生成出的媒体项随后进入 mediaLibrary，再复用视频路径的分段铺设逻辑。

六、手动动作覆盖流程

AvatarActionConsole.tsx 负责展示视频动作和序列帧动作。用户点击动作时，系统会找到播放头所在的 avatar-generated 父角色片段；如果正在播放，会先暂停并同步播放头，再插入动作覆盖。

  1. 调用 addAvatarActionOverlay(parentClipId, source, actionId)。
  2. 根据播放头时间，将动作开始时间限制在父角色 clip 的时间范围内。
  3. 生成 kind: "avatar-action-overlay" metadata，并写入 parentGeneratedClipId。
  4. 视频动作直接创建 overlay clip；序列帧动作先按动作自身总时长渲染 WebM，再创建 overlay clip。
  5. overlay clip 被追加到已有动作覆盖轨道，或新建“人物视频动作覆盖 / 人物序列帧动作覆盖”轨道。
这个设计让手动动作不是破坏性替换父角色轨道，而是作为上层覆盖片段存在。预览时再根据 parentGeneratedClipId 临时隐藏对应父片段，保证动作期间不会出现底层角色和动作角色重影。

七、预览合成适配

Preview.tsx 增加了 avatar 相关 clip 识别函数，用来处理普通生成片段、序列帧生成片段和动作覆盖片段。

逻辑 目的
isAvatarGeneratedClip 识别自动生成的角色动画 clip。
isAvatarGeneratedSequenceClip 识别来源为 sequence 的角色动画 clip。
isAvatarActionOverlayClip 识别手动动作覆盖 clip。
getAvatarOverlayParentIdsAtTime 在某个时间点收集正在生效的 overlay 绑定的父 clip id。
shouldSuppressClipForAvatarOverlay 只隐藏被当前 overlay 绑定的父角色片段。

本次预览修正

  • 旧逻辑只要存在任意动作 overlay，就隐藏所有 avatar-generated 片段，容易误伤同一时间线上的其它角色片段。
  • 新逻辑按 parentGeneratedClipId 精确匹配，只隐藏当前 overlay 对应的父片段。
  • 多轨 canvas 渲染路径也使用同样规则，从已解码帧中移除被 overlay 覆盖的父帧。
  • 当存在 source: "sequence" 的生成片段时，禁用原生视频直出路径，走多轨 canvas 合成路径，避免序列帧类角色合成和覆盖关系失真。
  • 如果存在多个视频轨道未来还有 clip，也禁用原生播放路径，防止原生单轨播放无法正确表现多层合成。

八、生成物在时间线中的表现

生成类型 轨道名称 clip metadata 媒体形态
动作视频生成 人物视频动画 kind: "avatar-generated", source: "video" 复用用户导入的视频媒体。
序列帧生成 人物序列帧动画 kind: "avatar-generated", source: "sequence" 序列帧图片先编码为 WebM，再作为视频媒体铺设。
视频动作覆盖 人物视频动作覆盖 kind: "avatar-action-overlay", source: "video" 复用用户配置的手动动作视频。
序列帧动作覆盖 人物序列帧动作覆盖 kind: "avatar-action-overlay", source: "sequence" 按动作帧总时长编码为 WebM 后插入。

九、当前限制与注意事项

  • 序列帧编码依赖浏览器支持 Mediabunny 可用的视频编码器；不支持时会提示“当前浏览器不支持序列帧视频编码”。
  • 序列帧 idle/speaking 预渲染目前使用固定 5 秒循环素材，再由分段铺设逻辑复用。
  • 单图时长输入限制为 0.1 到 2 秒；底层编码保护最小时长为 0.001 秒。
  • 背景移除相关按钮当前由 ENABLE_BACKGROUND_REMOVAL = false 关闭，代码路径保留。
  • 动作覆盖依赖父角色 clip id。若后续支持复制、拆分、合并角色片段，需要同步维护 parentGeneratedClipId 关系。
  • 当前生成逻辑直接更新 project store，未通过完整 ActionExecutor 执行；配置保存有 actionHistory，时间线生成插入本身还可继续补齐撤销/重做一致性。

十、后续建议

  • 为 generateAvatarFromSequence 和 overlay 插入补充单元测试，覆盖 metadata source、父片段绑定和轨道插入顺序。
  • 把序列帧预渲染时长从固定 5 秒升级为可配置或按音频分段动态生成，减少重复媒体和无效编码。
  • 为动作覆盖提供时间线可视化标识，例如在 clip 标题中展示动作名和来源。
  • 补齐生成动作的撤销/重做能力，让时间线插入和 mediaLibrary 增量与项目历史保持一致。
  • 增加导出链路回归验证，确认序列帧 WebM alpha、overlay 隐藏父片段、多轨合成在最终导出中表现一致。
